METHODOLOGY

A transparent path from forecast error to confidence.

The prototype separates source data, historical error behaviour, machine-learning inference, and user-facing explanation.

01

Forecast

Numerical weather prediction fields for the selected lead time.

02

Reference

Reference observations or reanalysis used to establish forecast error.

03

Error history

Historical forecast-error behaviour associated with comparable conditions.

04

ML inference

Estimate where forecast behaviour is likely to be less reliable.

05

Confidence

Convert model output into a spatial and lead-time confidence view.

DATA SPECIFICATION

Prototype data specification.

Domain
5–40°N, 65–100°E analysis window; India land area aggregated for display.

Horizon
Day 1–10 = 24–240 h lead time (0 h excluded).

Forecast source
ECMWF IFS HRES via WeatherBench 2, 1.5° grid, 00/12 UTC runs, 2016–2022.

Reference source
ERA5 via WeatherBench 2, 6-hourly. Labels are forecast-vs-reanalysis error, not station observations.

Evaluation
Chronological split: train 2016–2020, validate 2021, test 2022. Bust thresholds come from the historical error distribution and are frozen before final testing.

Implementation note

This specification is pending data-access validation. Dataset names, versions, temporal splits, and preprocessing parameters must be locked to the verified project data pipeline before presenting them as final system specifications.

UPLOADED DATA

The Indian Weather Repository CSV (118,298 readings, 29 Aug 2023 to 4 Apr 2024) is converted into a data file in data/ (built by tools/build_data.py) and is a development sample for the map viewer. It is not the verification source (ERA5) and is not substituted for HRES forecast fields.
